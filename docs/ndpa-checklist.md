# NDPA checklist

How KiloMita handles personal data, checked item by item against the Nigeria Data Protection Act 2023 (NDPA). Each item is either backed by code and a test, or marked **open** for the maintainer to decide.

**This is not legal advice.** It is an engineering record written by the project, not by a lawyer. Section numbers are given only where the statute text was quoted in the sources checked (2026-11-04). Every other item names the topic and says "section to confirm against the Act". Before relying on any item, read it against the Act itself and the Nigeria Data Protection Commission's General Application and Implementation Directive (GAID 2025).

Sources:

- Nigeria Data Protection Act 2023, as published by the Commission with the GAID: <https://ndpc.gov.ng/wp-content/uploads/2025/07/NDP-ACT-GAID-2025-MARCH-20TH.pdf>
- the statute text as hosted by DataGuidance: <https://www.dataguidance.com/sites/default/files/data_protection_act_2023.pdf>

## What personal data exists

| Data                                                                                                           | Where                                                                       | Kept for                                                                     | Who can link it to a person                                                               |
| -------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- | ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| IP address                                                                                                     | Seen by Vercel, our functions, and the test server on every request         | Not stored by our code. Vercel keeps its own request logs (1 hour on Hobby). | The ISP, with its own records                                                             |
| Hashed IP prefix (/24 or /48, HMAC with a daily random salt)                                                   | `results.ip_hash`, only for shared results and only with `CLIENT_IP_HEADER` | Wiped after about 48 hours; the salt is deleted at UTC midnight              | On the day it is made, anyone holding the salt and the database could test prefixes       |
| Rate-limit keys (HMAC of the full IPv4 address or IPv6 /64 and /48, same daily salt)                           | Upstash, `rl:*` keys                                                        | Until their window ends: a minute, an hour or the UTC day                    | On that day, anyone holding Redis could brute-force an IPv4 address (2^32 tries)          |
| A shared result: speeds, latency, jitter, data used, duration, time, ISP, state, connection type, device class | Neon, `results`                                                             | 12 months                                                                    | Not directly. Small groups are hidden, and published numbers are bands and rounded values |
| Per-result secret (SHA-256 on the server; the secret itself on the device)                                     | Neon `results.owner_hash`; the visitor's `localStorage`                     | With the result                                                              | Only the device holding the secret                                                        |
| Outcome counts (how a test ended, profile, server id)                                                          | Upstash `m:h:*` and `m:d:*` hashes                                          | 100 days                                                                     | Nobody: no identifier is stored with them                                                 |

## When something changes

Any change to what is stored, for how long, or where must update `/privacy`, its e2e assertions and this file in the same commit (CLAUDE.md, "Consent and privacy").
